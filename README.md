### Deep dives

<details>
<summary><b>webserv — request lifecycle, architecture and engineering challenges</b></summary>

<br>

**Highlights**

- **Non-blocking event loop.** One thread multiplexes every listening and client socket through `epoll()`. Partial reads and partial writes are carried across loop iterations via `EPOLLOUT`, so no single request can ever block the server.
- **Incremental request parsing.** Detects header termination (`\r\n\r\n`) and consumes bodies through both `Content-Length` and **chunked transfer encoding**, reading only what is available on each event.
- **Hand-written configuration parser.** A tokenizer and recursive parser for an NGINX-style config compile directives into a `Server` / `Location` object tree that drives routing, method validation and per-server `client_max_body_size` limits.
- **CGI execution.** `fork` + `pipe` with full RFC-compliant environment setup (`REQUEST_METHOD`, `QUERY_STRING`, `PATH_INFO`, `CONTENT_TYPE`, `CONTENT_LENGTH`), streaming the request body to the child's stdin and parsing CGI-generated headers back out.
- **Feature set.** Virtual hosting with `server_name` matching, directory autoindex, configurable per-server error pages, `301`/`302` redirects, `multipart/form-data` uploads with boundary parsing, MIME type resolution and URL decoding.

**Request lifecycle**

```
Startup      main() → ParseConfig → Server[] / Location[]
             OpenConnection::initServer()  socket → bind → listen → register in epoll

Event loop   epoll() on all fds
               ├── EPOLLIN on listener  → acceptNewConnection()  accept + register client fd
               └── EPOLLIN on client    → handleClientData()     incremental read

Routing      matchServer()      select virtual server by Host header + port
             HTTP::handleRequest()
               1. parseRequest()    method, URI, headers
               2. matchLocation()   longest-prefix route match
               3. validate          method allowed? body within limit?
               4. dispatch          GET → serve / autoindex
                                    POST → upload or executeCGI()
                                    DELETE → unlink
               5. buildResponse()   status line + headers + body

Write        sendResponse()     partial sends resumed across epoll cycles
Cleanup      closeConnection()  deregister fd → close()
```

**Class responsibilities**

| Class | Role |
|---|---|
| `ParseConfig` | Tokenizes the `.conf` file and builds the `Server`/`Location` tree |
| `Server` / `Location` | Hold per-server and per-route configuration |
| `OpenConnection` | Socket lifecycle and the `epoll` event loop |
| `HTTP` | Request parsing, routing, handler dispatch, response building |
| `HelperFunc` | MIME types, URL decoding, shared utilities |

**Engineering challenges**

- **No blocking calls anywhere.** Every `read`, `write` and `accept` had to tolerate returning partial data, which means per-client state machines rather than straight-line code.
- **C++98 only.** No `auto`, no range-based `for`, no smart pointers, no `std::to_string` — ownership and lifetimes are managed explicitly.
- **Protocol correctness from the RFC.** Chunked decoding, header folding, status-code semantics and CGI header merging were implemented from the specification rather than a reference library.
- **Reaping CGI children** without blocking the event loop, and cleaning up their pipes on client disconnect.

</details>

<details>
<summary><b>minishell — pipeline stages and engineering challenges</b></summary>

<br>

```
input ──► LEXER ──► EXPANSION ──► PARSER ──► EXECUTION ──► output
         tokenize    $VAR, $?      command      fork/exec
         + quotes    resolution    structures   + pipes
```

**Highlights**

- **State-machine tokenizer** handling single- and double-quoting rules, operator recognition and ambiguous-redirect detection, feeding a parser that builds the command and redirection structures.
- **Pipeline execution** with `fork` / `pipe` / `dup2` process orchestration and `PATH` resolution for external commands.
- **All four redirection types** — `<`, `>`, `>>` and heredoc (`<<`) — with correct `open` flags per type and heredoc input loops.
- **Seven built-ins** (`echo`, `cd`, `pwd`, `export`, `unset`, `env`, `exit`) with Bash-accurate exit statuses and environment mutation.
- **Bash-accurate signal semantics** for `SIGINT`, `SIGQUIT` and EOF across interactive, in-pipeline and heredoc contexts.
- **Custom tracking allocator** that registers every heap allocation, enabling deterministic single-call cleanup and **zero leaks under Valgrind**.

**Engineering challenges**

- **Quoting is context-dependent.** `'$VAR'` must stay literal while `"$VAR"` expands, and expansion happens *after* tokenizing but *before* parsing — getting that ordering wrong breaks everything downstream.
- **File-descriptor hygiene.** Every `dup2` in a pipeline needs its original descriptor closed in both parent and child, or the shell hangs waiting on a pipe that never sees EOF.
- **Signals behave differently** in the interactive prompt, inside a running child, and during a heredoc read — three distinct handler configurations.
- **Memory discipline** without a garbage collector in C, solved by making one instead: a tracking allocator that owns every pointer.

</details>

</details>

<details>
<summary><b>cub3D and philosophers — technical detail</b></summary>

<br>

**cub3D**

- **DDA raycasting.** One ray per screen column; horizontal and vertical grid intersections are computed independently and the nearer hit wins.
- **Fisheye correction** through perpendicular-distance projection: `wall_height = TILE_SIZE / perpendicular_distance × dist_to_projection_plane`.
- **Validating scene parser** for `.cub` files — directional wall textures (NO/SO/WE/EA), floor and ceiling RGB values, map enclosure verification and player start position — rejecting malformed maps before a single frame is drawn.
- **Per-direction texture mapping** with pixel-level color extraction and texture-coordinate computation per ray.
- **Smooth input** via boolean key-state tracking, so multiple keys held at once (WASD + arrows + sprint) compose correctly, plus a toggleable minimap.

**philosophers**

- **One mutex per shared resource**, with a separate mutex guarding printed output so status lines never interleave.
- **Deadlock avoidance without a central arbiter** — parity-ordered fork acquisition plus a staggered thread start breaks the circular-wait condition.
- **Starvation detection.** A dedicated monitoring thread compares each philosopher's `last_meal` timestamp against `time_to_die` at millisecond resolution and raises a shared stop flag.
- **Clean shutdown.** All threads observe the stop flag, are joined, and every mutex is destroyed — no leaks, no orphaned threads.

</details>

**[minitalk](https://github.com/obbad-dev/minitalk)** — *C, UNIX signals, IPC*
A client/server messaging system built **only on `SIGUSR1` / `SIGUSR2`** — no sockets, no pipes. The client encodes each character bit by bit (MSB→LSB); the server reassembles bytes in a `SA_SIGINFO` handler and acknowledges every bit back to the sender. The per-bit ACK handshake is what makes transmission reliable despite signals having no queueing guarantees.

<summary><b>Algorithms &amp; C Fundamentals</b></summary>

<br>

**[push_swap](https://github.com/obbad-dev/pushSwap)** — *C, algorithms, data structures*
Sorts integers across two stacks using only a restricted operation set (`swap` / `push` / `rotate` / `reverse rotate`), minimizing total move count. Uses **rank compression** to map values onto `1..n`, a **chunked bucketing pass** with a sliding rank window (10 for ≤100 elements, 30 beyond), and position-aware rotation selection — choosing rotate vs. reverse-rotate by which half of the stack the target sits in. Specialized routines handle sizes 2, 3 and ≤7 directly.

**[libft](https://github.com/obbad-dev/libft)** — *C, static library*
A reimplementation of a practical subset of the C standard library, packaged as `libft.a`: memory operations (`memset`, `memcpy`, `memmove`, `memchr`, `memcmp`), string manipulation (`strlen`, `strlcpy`, `strlcat`, `strnstr`, `split`, `substr`, `strjoin`, `strtrim`), conversions (`atoi` with overflow handling, `itoa`), character classification, file-descriptor I/O, and a singly linked list API — all built on `write` and `malloc` alone.

**[ft_printf](https://github.com/obbad-dev/ft_printf)** — *C, variadic functions*
A drop-in `printf` replacement covering `%c %s %p %d %i %u %x %X %%`, writing directly through `write(2)` with no stdio buffering. Uses `va_list` for variadic dispatch and recursion for digit emission, so higher-order digits print first without intermediate buffers, while returning an accurate count of bytes written.

**[so_long](https://github.com/obbad-dev/so_long)** — *C, MiniLibX, graph traversal*
A 2D tile-based game with a full map-validation pipeline: rectangularity, character-set validation, wall enclosure, and **flood-fill reachability** proving every collectible and the exit are actually reachable from the player's start before the game launches. Rendering and event handling run through MiniLibX with per-facing player textures.

</details>
